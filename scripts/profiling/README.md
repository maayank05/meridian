# Phase 2 profiling scripts

These scripts produced the committed Phase 2 reports in [`docs/data/`](../../docs/data/). They read the Olist CSVs **read-only** and write **aggregates only**: no record identifiers, no review text, no raw rows.

| Script | Purpose |
|---|---|
| `profile_olist.py` | Pandas profile of all 9 files (every column read as text) → `profile.json` |
| `followups.py` | Follow-up aggregates (fan-out, review timing, DST hours, reconciliation profiles) → `followups.json` |
| `verify_stdlib.py` | Independent re-computation of 33 key figures with `csv` + `Decimal` (no pandas); exits non-zero on any difference |
| `build_reports.py` | Generates the profiling report, data dictionary, DQ register, relationship report and `profile_results.json` from the two JSON files |

## Reproduce the Phase 2 results

From the repository root, with the virtual environment set up (see the main README) and the Olist CSVs in `data/raw/olist/`:

```powershell
$py = ".venv\Scripts\python.exe"
New-Item -ItemType Directory -Force build\profiling, build\profiling_docs\docs\data | Out-Null
& $py -I scripts\profiling\profile_olist.py data\raw\olist build\profiling\profile.json
& $py -I scripts\profiling\followups.py     data\raw\olist build\profiling\followups.json
& $py -I scripts\profiling\verify_stdlib.py data\raw\olist build\profiling\profile.json   # expect: 33 matched, 0 differed
& $py -I scripts\profiling\build_reports.py build\profiling build\profiling_docs
```

Outputs go to `build/` (gitignored), never next to the raw data. To confirm the committed reports are reproduced, compare each file in `build\profiling_docs\docs\data\` with `docs\data\`. On 2026-11-06 all five generated files were **byte-identical** (see `docs/QUALITY_REPORT.md`). `KPI_IMPACT.md` and `SOURCE_HEADERS.md` were written separately and are not regenerated by these scripts.

Tests on the synthetic fixture: `pytest scripts/profiling/tests`.
